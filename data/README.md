# Data

| Folder | Contents | Rules |
|---|---|---|
| `manifest/runs.csv` | Every planned run, in randomised execution order | Generated by `modegrid plan`. Regenerate only before the first capture |
| `captures/` | One `<run_id>.md` per run: front-matter, verbatim final answer, reasoning trace, run notes | Write-once. Never edit an answer. Append dated notes only |
| `scores/` | `rater<N>.csv` blind sheets, `adjudicated-blind.csv`, `adjudicated.csv`, `adjudication-log.md` | Never overwrite another rater's sheet |
| `blinding/key.csv` | Blind id to run id | Kept out of git until every rater sheet is final (see `.gitignore`) |
| `pilot/` | LA-P1 DeepSeek captures | Exploratory only |

## Capture front-matter

| Key | Meaning |
|---|---|
| `run_id` | `<family>__<mode>__<prompt>__r<replicate>` |
| `family`, `vendor`, `mode`, `native_label` | Which cell, and the vendor's own name for the mode |
| `channel` | `api` or `web` |
| `model_requested`, `model_returned` | What was asked for and what the vendor said answered |
| `params` | Exact mode parameters sent |
| `prompt_id`, `prompt_sha256` | Instrument identity |
| `replicate`, `date_run`, `run_by` | Provenance |
| `finish_reason`, `usage`, `latency_s` | API runs only |

## Datasheet summary

- **Purpose:** test whether reasoning mode or model family explains more variance in
  answer quality on one constrained design task.
- **Composition:** 60 answers, 6 families x 2 modes x 5 replicates, plus scores from at
  least two blind raters.
- **Collection:** vendor APIs and one web UI, between the pre-registration tag and the
  end of collection. Dates are in each capture.
- **Sensitive content:** none. No personal data. The prompt describes a hypothetical
  workstation.
- **Licence:** CC-BY-4.0. Model output remains attributable to its originating system.
